## Data safety form

Does the app collect or share user data? **Yes, collects. Does not share**
(PayFast receives the order amount and reference on its own payment page;
the app never sends personal data to third parties for their own use).

Is all collected data encrypted in transit? **Yes** (HTTPS only).
Can users request their data be deleted? **Yes** — email
privacy@midfood.co.za (stated in the privacy policy and under Account).

| Data type | Collected | Shared | Required | Purpose |
|---|---|---|---|---|
| Personal info → Name | Yes | No | Required | App functionality, account management |
| Personal info → Email address | Yes | No | Required | App functionality, account management |
| Personal info → Phone number | Yes | No | Optional at sign-up | App functionality (the driver phones you) |
| Personal info → Address | Yes | No | Required to order | App functionality (delivery) |
| Location → Approximate / precise | Yes (only if the customer taps "Pin my location" at checkout) | No | Optional | App functionality (delivery) |
| Financial info → Purchase history | Yes | No | — | App functionality (your orders) |
| App activity → Other actions | No | | | |
| Device or other IDs | Yes (push notification token) | No | Optional | App functionality (order notifications) |

Payment info (card numbers) is **not** collected by the app — it is entered
on PayFast's own page.

## Testing track (personal developer accounts)

Personal accounts created after Nov 2023 must run a **closed test with at
least 12 testers opted in for 14 continuous days** before they can apply for
production access.

1. Testing → Closed testing → Create track "Family and friends".
2. Testers: create an email list; add 12+ Gmail addresses (the people already
   using midfood.co.za/app are the obvious ones).
3. Upload the `.aab` from the "Mobile app build" workflow with target
   **android** (production profile builds the Play bundle).
4. Share the opt-in link; testers must install from Play and stay opted in.
5. After 14 days: Dashboard → **Apply for production access**, answer the
   short questionnaire (what was tested, what changed), then roll out to
   production.
